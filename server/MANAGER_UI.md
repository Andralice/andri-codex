# 手机管家模块

侧栏在现有搜索框上方增加一行“管家”入口，沿用原侧栏样式。该页面通过手机网关的只读
`andri/monitor/overview` 查询事件、处理原因、已发起的跟进、后续审查结果及独立检查摘要。
每页默认40条，最大80条，使用创建时间与事件ID作为游标。打开模块、刷新和翻页不创建模型回合，
也不修改偏好、发送跟进或接管会话。“询问管家”打开配置中的同一个长期管家会话。

页面在工作记录之前展示“待你回答”和“通知”。`overview.inbox` 独立查询尚未回答的问题，
不会受工作记录首页40条限制；已回答、撤回或结束的事项不再算作待回答。
通知包含跟进受阻、跟进检查结束及独立检查返回/失败/过期，普通无须跟进的审查不生成通知。
独立检查详情保留发现、依据和验证边界；旧源回合报告明确标注不能代表当前进度。
三个列表各自分页：`cursor` 用于工作记录，`questionsCursor`、`notificationsCursor` 用于提问与通知；
`inboxLimit` 默认20、最大80。响应返回各列表数量及下一页游标，`pendingQuestionIds` 供刷新移除旧页已回答问题。
翻阅历史后仍定时刷新提问和通知。“前往回答”优先打开该事件匹配的现有原生问答；
尚无匹配问答时打开管家对话，由用户说明决定，不自动提交、默认选择或发出新的服务消息。
这不是系统推送或已读状态；旧服务器未返回 `inbox` 时客户端明确提示未支持汇总，不伪装为空列表。

网关给实际配置的管家会话添加 `andriRole=manager`，给有服务记录支持的回合和项目添加
`andriOrigin`，种类为 `monitor_review`、`monitor_notice`、`monitor_followup`。
原始 Codex 历史不删除、不改写；这些字段只影响手机客户端的展示。
来源依据实际数据库中的回合编号、待发送的完整提示，以及旧版本服务使用的确定性原生消息ID，
不是按普通用户文字中的“管家”或提示词前缀过滤。同一自动回合里的真实用户追加要求仍保留。

普通管家聊天隐藏后台审查及服务通知的自动内容，但原生提问、审批和错误保持可见。
原任务中的自动跟进及其执行过程、回答集中为默认收起的盾牌卡片，展开可读完整记录；
日常自动回合结束不再触发普通任务完成提醒。原生问题及审批的交互规则不变。
内部检查工作会话不会因为流式通知进入普通侧栏；原生请求及其解除通知仍转发。

网关启动参数 `--monitor-runtime` 指向管家运行目录，默认使用本仓库的
`codex/task-monitor/runtime`。未配置或暂时不可读取时，模块返回明确的不可用状态；
普通对话照常使用。不应把“本轮已关闭”当成需求全部经过独立验收。

验证：

- `python3 -B -m unittest discover -s codex/checks -p 'test_task_monitor*.py'`
- `python3 -B -m unittest discover -s codex/checks -p 'test_thread_visibility.py'`
- `python3 -B codex/checks/check_manager_presentation.py`
- Gradle的 `ManagerPresentationCheck` 及聊天、历史分页、任务完成回归检查。

协议联调使用隔离的真实 app-server、网关和本机假模型，覆盖实时标识、历史保留、
同文用户消息、主动询问及隐藏工作会话中的原生提问/解除转发，不等同于手机真机界面验收。
该模块需要配套更新网关代码与安卓客户端；构建 APK 本身不会重启或部署服务器服务。
