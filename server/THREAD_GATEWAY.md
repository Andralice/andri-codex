# 手机与桌面共用对话

两个 Codex app-server 读取同一份会话存储，但每条对话只能有一个写入实例。
手机直接在自己的实例恢复桌面已加载的对话，会得到 `already has an active writer`。

`thread_gateway.py` 在原手机 Unix socket 接收 WebSocket 连接。全局查询和新对话仍发给
手机后端；包含 `threadId` 的请求先查询两个后端的 `thread/loaded/list`，发给已加载该
对话的实例。恢复对话时重新核对所属实例，不通过恢复操作探测或抢占写入权。
两个实例都未加载时采用手机后端；无法连接的桌面实例可能导致上游安全拒绝恢复，不能
把连接失败解释成已释放写入权。已有写请求在断线后不重放。

每个手机客户端连接各自拥有两个后端连接，保留原始初始化能力、通知、权限和工具清单。
全局设置的读取及修改仍属于手机后端；任务自身的执行设置则发给所属实例。
代理只转发本机 Unix socket，不提供 TCP 端口，不读取凭据，不执行模型指令。
手机后端仍由现有 `question_policy.py` 启动，继续移除异步提问工具。
桌面已有任务沿用桌面实例的工具与行为，不因手机查看而迁移或重启。

两个后端的 JSON-RPC 请求编号彼此独立。代理对模型发给用户的问题编号重新编号，
用户回答及 `serverRequest/resolved` 通知映射回对应来源；同一条回答不会转发给两个实例，
不会自动回答或选择默认项。重新连接后，通过恢复对话获取原实例重放的待回答问题。

## 安装与维护

保留原 `codex-mobile.service` 及凭据加载，将其监听路径改为独立的后端 socket。
按照 `thread-gateway.service.in` 安装额外服务，手机继续使用原入口路径。
切换前备份原启动脚本和服务配置，核对旧手机实例没有活动任务及未回答问题，再停止它。
移除旧入口的符号链接，启动新后端及代理；不停止桌面实例。

任务管家应直接扫描桌面及手机后端，避免把代理误当成第三个写入实例。
`monitor_socket` 继续指向实际持有管家对话的桌面实例；私有 MCP 的用户回合校验保持一致。

代理可以独立重启，后端任务继续运行；手机连接需重连。手机后端维护重启的空闲检查应
针对后端 socket，不能根据代理转发的桌面状态推断手机实例是否空闲。
回滚时先停止代理，再恢复旧手机启动脚本及管家连接配置，移除已停止的代理 socket，
重启手机后端。不要在有新手机任务或待回答问题时回滚。

## 验证

```sh
python3 -B codex/checks/check_thread_gateway.py
```

检查使用两个独立的已安装 app-server 和本机假模型，核对已有写入实例的恢复、
在手机与桌面对话之间切换、新任务留在手机实例、双方问题和回答转发、断线后的问题重放、
手机等待回答策略，以及相同问题编号的隔离。全部临时文件保存在 `codex/`，不调用上游模型。
手机实机页面是否成功加载仍需由实际手机客户端确认。
