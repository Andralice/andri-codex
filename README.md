# Andri Android

通过 SSH 操作 82 上 Codex 的 Andri Android 原生客户端，当前源码版本为 0.1.44（versionCode 45），最低 Android 8.0。

## 安装和连接

1. 安装 app/build/outputs/apk/debug/app-debug.apk。
2. 将已授权访问 82 的 SSH 私钥导入应用。不要选择 .pub 公钥；加密私钥还需要输入口令。
3. 默认地址 82.156.142.57:22，用户名 ubuntu。工作目录填写服务器上的绝对路径。
4. 点击连接后，新建或打开对话，用自然语言发送任务。

首次成功连接后，再次打开应用会使用已加密保存的私钥自动重连，并恢复上次打开的对话。返回对话列表不会清除这个记录。连接期间显示 SSH、身份验证、Codex 握手等具体阶段，可随时取消或打开历史版本；单次连接最多等待 45 秒，失败后返回可重试的页面。连接失败后可在连接页修改配置。主动选择“断开服务器”会停止自动重连，直到再次手动连接成功。

连接期间由 Android 前台服务和页面共享进程级会话，页面关闭或重建不会停止后台重连。服务通过带超时并持续续期的 CPU 唤醒锁维持锁屏后的心跳；监测默认网络切换，并在重连失败后持续退避重试。系统重建服务时会从加密存储恢复连接配置。回到应用时复用仍有效的连接并同步状态。主动断开或取消连接会停止服务、重试和唤醒锁。首次连接时 Android 13 及以上会请求通知权限。

“更多 → 后台连接设置”（连接页也有入口）可以查看系统电池优化状态并打开设置。建议为 Andri 允许后台运行、不优化电池，并按手机厂商要求开启自启动。持续连接会增加耗电；前台服务和唤醒锁不能绕过 Doze 的全部网络限制，Android 仍可能因系统策略、断网或进程被强制停止而中断连接。系统强行停止后的恢复时间由系统决定；用户手动强制停止后需要重新打开应用。

模型选项为 gpt-6-luna 和 gpt-6.1-sol，实际使用服务器的 provider 配置。

## 服务器连接

客户端在 SSH exec 通道内运行：

    codex app-server proxy --sock /home/ubuntu/.codex/mobile-control/app-server.sock

这个通道承载 WebSocket 握手和消息帧。不能把 proxy 当作逐行 JSON 通道。

82 上的 codex-mobile.service 使用 Ubuntu 用户运行 Codex。启动脚本读取已有的 /home/ubuntu/.codex/wyy22.env，服务会自动启动并在故障后重启。该密钥文件保持在服务器，未打包到 APK。服务通过权限为 700 的目录中的本地 socket 接受连接。

应用固定验证当前 82 的 Ed25519 主机密钥，并包含 Android 上处理该算法所需的加密实现。手机私钥使用 Android Keystore 和加密偏好设置保存，禁用云备份及设备迁移。

## 当前功能

- 使用选定的短发少女头像作为桌面图标，提供多分辨率与安卓自适应图标资源。
- 新建、恢复、列出对话，并支持对话列表分页；历史按最近 30 回合加载，可继续读取更早消息。
- 聊天页可打开 Codex 会话侧栏，搜索并切换已有对话或新建对话；侧栏对话直接使用 app-server 原生 thread。
- 多个对话同时执行，按消息 ID 分别接收流式回复。
- 对话运行期间可继续写消息并提交到 Codex 原生队列；由 Codex 在当前任务后按队列执行，队列状态从服务器同步并支持移除。
- 进入对话默认显示底部最新消息；向上翻阅历史时不强行滚回底部，顶部仍可加载更早消息。
- 命令/文件/权限审批队列，以及工具提出的问题。
- 聊天输入区默认收起为圆形按钮；查看长对话时不占用底部空间，点击后展开并保留草稿、图片和停止任务入口。
- 聊天菜单可通过 SSH/SFTP 浏览服务器目录，并为当前对话选择工作区、请求审批、自动审查或完全访问模式；保存后会重新从 app-server 核对实际采用的设置。
- 中断当前任务，切回应用时刷新状态或尝试重新连接。
- ViewModel 保持屏幕旋转期间的连接、消息和草稿。
- 连接成功或回到前台时通过 SSH 自动检查应用更新；对话列表和聊天页均有手动检查入口。
- 明亮白底、淡杏气泡与暖棕点缀，助手正文不重复显示身份栏，短消息气泡随内容收缩，输入框采用细边框和轻阴影；系统栏、菜单与审批窗口使用同一套配色。
- 图片选择和移除，支持文字附图或仅发送图片，最大 10 MB；通过 app-server UserInput 的 `image.url` 发送 data URL。
- 助手 Markdown 中的图片链接和工作区图片可加载显示；图片读取限制大小、像素与缓存占用，并跳过普通 HTTP 图片链接。
- 聊天图片可打开原图预览，支持双指缩放、拖动、重置缩放和下载原图。
- 对话列表的连接状态、筛选、计数、空状态和卡片变化带有过渡动画。
- 新建对话入口位于列表标题右侧，模型选择位于聊天输入区，空白对话有独立起始页；异常作为时间线中的紧凑状态条显示在对应任务位置，可展开详情。
- 设置中的推理强度使用暖色滑块：拖动连续跟随、松手吸附档位，切换和恢复默认时滑钮与填充同步缓动。
- 对话首页支持按标题、模型或项目搜索和“全部/进行中”筛选；列表按运行中与最近对话分组，显示项目归属与最近任务状态，并在顶部提供新对话入口。
- 会话列表使用白色卡片与浅色边框，长标题最多显示两行，摘要以纯文本展示，项目与时间独立排列；每条会话的“更多”菜单提供置顶、归档和删除，离线或任务运行期间禁用归档与删除。
- 对话可单独设置项目名称，和工作区目录分开保存；列表显示项目归属与最近任务状态，新任务显示尚未执行。
- 每次任务完成、失败或中断时显示约 4.5 秒的不阻塞提示；应用在后台时发送 8 秒后自动清除的手机顶部高优先级通知，并在对话列表记录结果。
- 离线时从本机缓存显示最近的对话和消息；连接恢复后再与服务器同步。
- 工具提问的选择项卡片显示更清晰，并支持多行自定义回答。
- 支持上传原画质视频（MP4、MOV、M4V、3GP、WebM、MKV、AVI，最大 1 GB），并在对话中播放或下载工作区视频。
- 支持从 QQ、微信等应用分享单个或多个文件到对话；文件上传至项目的 `codex/inbox`，每次最多 20 个、总大小最大 512 MB，发送前会保存在手机私有缓存中并跨进程恢复。
- 对话菜单新增项目文件浏览器，可预览常见文本/图片文件、保存到手机、分享或用其他应用打开；新增只读 Git 暂存与未暂存改动审阅。
- 输入区提供任务工作区，分为上下文、服务器文件、网页和代码改动标签；可引用或预览工作区文件、浏览并读取网页、审阅 Git 差异，并管理随下一条消息提交且在进程重启后恢复的上下文与附件。
- 后台任务提醒未送达时显示权限或通知渠道原因；有可用 SSH 连接时会回传诊断记录。
- 聊天中的网页链接可直接在应用内打开 HTTPS 预览，浏览后关闭即可回到对话。
- 新对话首条任务完成后，会根据消息内容自动生成简短标题。

## SSH 应用更新

首次手动安装当前 APK。已安装 0.1.2 或更新版本时，可使用内置 SSH 更新；0.1.1 及更早版本需要先手动安装。后续必须使用同一签名和更高 versionCode。

版本清单位于 82 的 /home/ubuntu/codex/mobile-client/releases/latest.json。更新包通过当前 SSH 会话的 SFTP 通道下载，无需新增公网端口、网站或手机内保存中转 Token。

0.1.10 起，点击下载前会重新读取服务器的最新清单，直接下载当前最新版，无需逐版升级；下载完成后再次确认版本。点击安装前重新校验包大小、SHA-256、包名、版本号和签名，并再次读取最新清单；期间如果发布了新版，旧包会被删除，提示下载最新版。清单读取失败会清除旧版本提示和缓存安装包，必须重新检查后才能继续。

确认更新包后交给 Android 系统安装；首次需允许此来源安装应用，授权后返回应用再次点击安装。自动检查在应用连接或回到前台时进行，不在后台静默安装。已安装旧版的用户建议先用当前 APK 覆盖安装一次，以启用修复后的更新逻辑；不要卸载，以保留连接配置和私钥。

连接页、正在连接页面、公共菜单和更新弹窗提供“历史版本与恢复下载”。历史列表通过独立 SSH/SFTP 读取 `history.json`，无需 Codex app-server 连接成功；可选择版本、校验下载、保存 APK 到手机，或交给系统安装器。历史下载固定使用选中的版本，不会因出现新版而被替换。安装前仍校验大小、SHA-256、包名、版本和同一应用签名。

Android 通常禁止旧 versionCode 覆盖新版；历史原包可以下载并打开安装器，但应用无法绕过系统的降级限制。不要为降级贸然卸载：卸载会清除本机连接私钥、配置和缓存，服务器对话保留。

已有发布包可运行 `python3 codex/build-history-index.py --release-root <发布目录> --output <发布目录>/history.json` 建立历史清单；只收录固定 release 证书签名且包名正确的 APK。后续发布自动维护历史清单，不覆盖或清理旧 APK。

服务器端版本使用 `codex/build-release.sh` 构建签名 APK，再运行 `codex/publish-server-update.sh` 更新本机的自动更新包和清单。发布脚本会核对包名、固定签名证书、SHA-256 和递增的 versionCode，并原子替换 `latest.json`。不要用旧的 `codex/publish-update.ps1` 发布服务器 release 版本；它用于 Windows 上的调试包流程。

当前界面交互预览位于 codex/mobile-redesign-preview.html，为对应 Compose 布局的示例页面，不连接真实服务，也不代表安卓真机截图。旧的 codex/codex-mobile-preview.html 保留用于对照。

## 构建和检查

需要 JDK 17、Android SDK 35、Gradle 8.9。SDK 路径由 Android Studio 或 ANDROID_HOME 提供。示例：

    $env:JAVA_HOME='D:\JDK'
    $env:ANDROID_HOME='D:\AndroidSDK'
    .\gradlew.bat assembleDebug lintDebug --no-daemon --max-workers=1

### Release 签名

服务器 release 包使用长期 release 签名密钥，存放在 `~/.android/andri-release.jks`，Gradle 密码只在 `~/.gradle/gradle.properties` 中。0.1.17 及之后由服务器同一密钥签名的版本可以原位升级。密钥权限设为仅服务器用户可读；不要提交或发送 keystore。请另行制作受保护的离线备份，丢失后将无法继续原位更新。

如果要构建 release 变体并保持自动更新兼容，把原 keystore 路径、密码和别名写入本机 `~/.gradle/gradle.properties`，不要提交到仓库：

    ANDRI_RELEASE_STORE_FILE=<原 keystore 的绝对路径>
    ANDRI_RELEASE_STORE_PASSWORD=<本机填写>
    ANDRI_RELEASE_KEY_ALIAS=<原密钥别名>
    ANDRI_RELEASE_KEY_PASSWORD=<本机填写>

服务器 release 密钥已配置，无需再次生成。打包 ZIP 运行 `codex/build-release.sh`；发布到自动更新目录运行 `codex/publish-server-update.sh`。ZIP 内的 APK 可用于手动安装；同一证书签名且 versionCode 递增的版本也可通过应用自动更新。若上架 Google Play，应另行使用 Play App Signing。

检查脚本位于 codex/checks。当前 Windows/JDK 17 对中文路径的 Gradle 测试 worker 参数文件存在编码问题，因此使用以下脚本编译检查后直接运行 JUnit：

    .\codex\run-checks.ps1

带真实 SSH/模型调用的检查需要显式提供本机密钥路径。测试只从该路径读取密钥，不会把密钥复制到项目：

    .\codex\run-checks.ps1 -SshKeyFile 'C:\Users\35243\.ssh\id_ed25519'

真实调用会创建少量检查对话；工具检查仅执行带 MOBILE 标记的 printf/sleep 命令，不修改项目文件。构建、连接诊断和原始检查日志均放在 codex。

## 验证边界

APK 构建、Android Lint 和 JVM 上使用同一客户端代码的真实服务器调用，不等于安卓手机上的完整验收。当前没有连接实体手机或配置可用模拟器，仍需要在目标手机确认安装启动、密钥导入、输入法、后台切换和网络切换。

应用尚未实现语音和远程推送；Git 改动视图提供只读文本差异。Android 杀死应用进程后，重新打开时自动恢复连接和上次对话；服务器服务独立运行。
